# Any Player

Any Player is a desktop music player written in Rust with a [Slint](https://slint.dev) UI. It brings
your streaming and self-hosted libraries into one place:

- **Spotify Connect control**: browse and control playback on any of your Spotify devices.
- **Local streaming** from **Jellyfin** and **Plex** servers, decoded and played on this machine.
- **Mixed queue**: Spotify, Jellyfin and Plex tracks can sit in the same queue.
- **Custom playlists**: `STANDARD` (hand-picked tracks) and `UNION` (combined from other playlists, deduplicated).
- **Sync** of app state, playlists and settings with other Any Player clients (Android companion).
- **Transfer**: export and import your state as an `any-player-state` file (optionally encrypted).
- **Remote AI DJ**: scheduled DJ breaks generated by a remote service and mixed between songs.
- **Tray icon and OS media controls** (MPRIS on Linux, SMTC on Windows, Now Playing on macOS).

## Prerequisites

All platforms: the stable [Rust toolchain](https://rustup.rs) (edition 2024, Rust 1.85 or newer).

### Linux

Install build dependencies (Debian/Ubuntu names):

```sh
sudo apt install libasound2-dev libdbus-1-dev libxkbcommon-dev libfontconfig1-dev libfreetype-dev
```

A Secret Service keyring (GNOME Keyring, KeePassXC, KWallet with Secret Service enabled) must be running;
provider credentials and tokens are stored there.

### macOS

Xcode command line tools (`xcode-select --install`). Secrets are stored in the login Keychain.

### Windows

MSVC build tools (Visual Studio Build Tools with the "Desktop development with C++" workload). Secrets are stored
in Windows Credential Manager.

## Build and run

```sh
cargo run -p any-player                # normal start
cargo run -p any-player -- --demo      # fake in-memory data, no network, no keyring
cargo run -p any-player -- --minimized # start hidden in the tray
```

Use `--release` for an optimized build.

## Tests and lint

```sh
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all -- --check
```

Tests are offline and deterministic; see [CONTRIBUTING.md](CONTRIBUTING.md).

## Packaging

Installers are built with [cargo-packager](https://github.com/crabnebula-dev/cargo-packager):

```sh
cargo install cargo-packager --locked
cargo packager --release -p any-player --formats deb,appimage     # Linux
cargo packager --release -p any-player --formats dmg              # macOS
cargo packager --release -p any-player --formats nsis             # Windows
```

Output goes to `target/release/bundle/`. The bundle identifier is `rocks.nesbitt.any-player.app`.

## Workspace layout

| Path | Responsibility |
|---|---|
| `crates/ap-model` | Pure domain model, wire formats, signatures. No IO, no async runtime |
| `crates/ap-store` | SQLite storage and migrations, settings, keyring secrets, platform paths |
| `crates/ap-providers` | Jellyfin, Plex and Spotify Web API clients, authentication, retry |
| `crates/ap-library` | Catalog cache, playlist repository, transfer and config import/export |
| `crates/ap-playback` | Playback engine, local audio backend, Spotify Connect backend, persistence |
| `crates/ap-sync` | Sync client and engine |
| `crates/ap-dj` | Remote AI DJ: break scheduling, passages, voice processing |
| `crates/ap-platform` | Media controls, tray, single instance, OAuth loopback, Spotify launcher |
| `app` | The `any-player` binary: Slint UI (`app/ui`), view models, startup wiring |
| `fixtures` | Cross-platform golden vectors generated from the Android app |
| `docs/DESIGN.md` | Full design document |

## Upgrading from the Tauri version (0.1.x)

Version 2 upgrades in place: same bundle identifier, database, cache and keyring locations. On first run it
migrates automatically:

- the legacy `playback_state.json` becomes the queue and player settings (the file is renamed to
  `playback_state.json.migrated-v2`);
- provider credentials in the keyring are read as-is;
- old cache files are deleted and the catalog cache is rebuilt from the network.

Sync settings lived in webview storage and are **not** migrated: re-enter them once in Settings → General. A new
sync client id is generated.

Rollback: v2 only adds tables and columns to the database, which the old app ignores, so reinstalling 0.1.x keeps
your data. Only the queue is lost, unless you rename `playback_state.json.migrated-v2` back to
`playback_state.json`.

## Spotify notes

- Any Player controls Spotify through **Spotify Connect only**; it does not decode Spotify audio itself.
- A Spotify client must be running on some device (phone, desktop app, speaker) for Any Player to control.
- Spotify **Premium** is required for playback control.
- Sign-in uses a loopback redirect: register `http://127.0.0.1:8989/login` as a redirect URI in your Spotify
  developer app.
